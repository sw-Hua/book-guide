# book-guide

把难啃的书做成「背景 ＋ 原文 ＋ 解释」三段式的导读版。

原文一字不改，只在每一节前面补背景、后面补解释。产出两个文件：可以听的 EPUB，和可以直接喂给 TTS 的纯文本朗读稿。

---

## 这本书说的是什么

读一本典故密集的书，真实流程是这样的：

```
读原文 → 卡住 → 查这是谁、哪本书、什么年代 → 回去重读 → 才算懂
```

一本三百页的书，这条路要走几百遍。走不完，就放下了。

`book-guide` 把这条链一次性做完，结果长这样：

```
【背景】《庄子·秋水》写于战国中后期，秋水篇借河伯与北海若的七番问答展开。
        “虚”在这里不是空无，指所居之处；“时”指时令。井蛙、夏虫两句是并列的比喻。

【原文】井蛙不可以语于海者，拘于虚也；夏虫不可以语于冰者，笃于时也。

【解释】庄子用的不是修辞，是论证：认知的边界由处境划定，不由智力划定。
        他把“不能理解”归因于位置，而不是归因于笨。这一句常被当成骂人的话引用，
        原文里讲的却是限制的来源。
```

背景给的是查得到的事实，解释点的是作者的动作。两者都不碰原文一个字。

打开阅读器，或者扔进任何 TTS App，戴上耳机就能顺着听下去。
不用停下来查，也不用在三个 App 之间来回切。

## 和别的「AI 读书」有什么不同

| | 常见做法 | book-guide |
|---|---|---|
| 原文 | 改写、缩写、总结 | **一字不动** |
| 立场 | 输出观点 | 只给事实与机关 |
| 结构 | 一章一篇读后感 | 一节一组，跟着原文走 |
| 用途 | 读完就忘 | 可反复听，可当注疏本存着 |
| 语气 | 形容词堆叠 | 有硬性禁词表，写完机器能查 |

最关键的一条：**原文不动**。改写过的书不再是原作者写的，读者听到的是模型的文风。这套流程里，模型只做两件事，补背景、点机关，其余全部交还原作者。

## 三十秒上手

```bash
# 1. 拆书：EPUB → 单元 + 作业稿
python3 scripts/extract.py --epub "book.epub" --out work/

# 2. 写注解（这一步由人和模型协作完成，格式见 templates/annotation.md）
#    存成 work/anno/b1.json  {"u012": {"bg": "...", "ex": "..."}}

# 3. 质检
python3 scripts/check.py --anno work/anno --units work/units.json

# 4. 出成品
python3 scripts/build.py --units work/units.json --anno work/anno \
    --epub "book.epub" \
    --out "book_导读版.epub" --txt "book_朗读稿.txt" \
    --title "书名（导读版）"
```

依赖：`beautifulsoup4`。没有别的。

```bash
pip install beautifulsoup4
```

## 两个成品怎么用

**`_导读版.epub`**
用 Apple Books、微信读书、Kobo、Calibre 都能打开。背景与解释用灰底左边框标出，和原文区分得开，不会看串。

**`_朗读稿.txt`**
纯文本，段落之间用空行隔开，`【背景】【原文】【解释】` 三个标记各自独立成段。丢进任何支持文本导入的 TTS（讯飞有声、Edge 朗读、iOS 朗读屏幕、ElevenLabs），照着念就行。标记本身会被念出来，正好当章节提示音。

## 三种模式

| 模式 | 做什么 | 什么时候用 |
|---|---|---|
| `full`（默认） | 全书每节都加 | 典故密集，通读 |
| `spot` | 只给典故和术语密集处加 | 其余直读，只想补关键处 |
| `essay` | 只加篇章级导言 | 已有基础，想理清脉络 |

## 写注解的七条铁律

这七条是这套流程的全部价值所在。违反任何一条，产出就会退回成「AI 读后感」。

1. **背景只给事实。** 谁、哪本书哪一卷、什么年代、术语原义。不评价、不预告、不剧透。
2. **解释说作者在做什么，不说他想告诉我们什么。** 有反讽就指明反讽落在哪一句。
3. **不复述原文。** 读者刚读完，不要再说一遍情节。
4. **一个概念只解释一次。** 后文再出现，不再展开。
5. **一句一个意思，平均 22 字。** 这是给耳朵听的，长句在车厢里会散。
6. **禁词**：意味深长、耐人寻味、发人深省、不禁让人、某种程度上、不得不说、恰恰、深刻、洞见、底层逻辑、闭环。出现即删。
7. **不用破折号，不用「首先／其次／最后」，不用比喻讲概念。**

`scripts/check.py` 会自动查第 5、6、7 条。

## 什么时候不该用

- **小说**：背景段会切断叙事，读起来像被人不断拍肩膀。
- **技术手册**：没有典故可补，加了只是复述。
- **绘本、画册**：文字量不够，切不出单元。

这套流程是为**引经据典的人文社科书**设计的。哲学的、历史的、金融史的、文学评论的，都合适。

## 实战记录

第一次跑这套流程，处理的是某本典故密集的金融类中文译作。

- 正文 11.7 万字，切成 157 个单元，平均 746 字
- 补写背景 157 段、解释 157 段，合计 1.8 万字
- 修 OCR 错字 6 处（译名、断段）
- 成品：导读版 EPUB 与朗读稿 TXT 各一份

耗时主要在写解释上。写一段解释的时间，大约是读三遍那段原文的时间。

注：本仓库不含任何书籍原文或其加工产物。工具只处理你有权处理的文本。
